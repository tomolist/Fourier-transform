# コードフォルダ 説明書

圧力経時変化のフーリエ変換（FFT）用ノートブック **7本** と共通モジュール1本。

## このコード群の目的

**全加工対象ファイルに適用するローパスフィルタのカットオフ周波数を決めること。**

末端フォルダを複数持つフォルダを指定し、その配下の全ファイルの周波数成分を
横断して把握します。

> ### 🎯 カットオフを決めたいなら → **07_カットオフ周波数決定_全ファイル横断.ipynb**
> 両形式をまとめて1つの集計にし、両対数のPSDグラフ・累積パワー曲線・
> カットオフ掃引表・CSVを出します。**まずこれを実行してください。**
> 01〜06 は個別のファイルや条件を細かく見るための補助です。

計測器が2種類あり **CSVの形式がまったく違う**ため、01〜06 は2系統に分かれています。
07 は両方をまとめて扱います。

## 1. 早見表

### 手元のCSVの「1行目」で形式を見分ける

```
CSVの1行目
├─ "Time:2026/08/05 16:10:15" のように Time: で始まる
│    → Futaba形式  → 01 / 02 / 03
│
└─ "#BeginHeader,71" のように #BeginHeader で始まる
     → NR-500形式（KEYENCE） → 04 / 05 / 06
```

ファイル名に `_futaba` が付いていれば Futaba形式ですが、
**付いていないファイルもあるため 1行目で判断するのが確実**です。
01〜06 は形式が合わないファイルを渡すと、落ちずに「もう一方を使ってください」と案内します。

### ファイル一覧

|---|---|---|
| **07**_カットオフ周波数決定_全ファイル横断 | **両方** | **カットオフ決定用（本命）** |
| 01_Futaba1ファイル用 | Futaba | 1ファイルだけ画面で確認 |
| 02_Futaba複数全ファイル用 | Futaba | 全ファイルを1枚ずつPNG＋CSV |

## 2. 実行タイミングの指針

**① まず 01 / 04 で1ファイルだけ見る**
新しい計測データを触るとき、最初に1ファイル開いて
ピーク値・立上り時間・f99.9・ノイズRMS が想定どおりか確認します。保存はしません。

**② 次に 07 でカットオフを決める**
本命です。全ファイルを横断集計し、推奨カットオフとその根拠を出します。

**③ 03 / 06 は条件ごとの傾向を見るとき**
温度・板厚などの条件ごとに重ね描きしたグラフが要るときに使います。

**④ 02 / 05 は原因調査用**
③で1本だけ極端に外れた線があるとき、個別PNGで犯人を特定するために使います。

## 3. 解析設定（01〜06 共通）

各ノートブックの**セル1**に解析設定があります。

```python
ZERO_ADJUST      = ...      # ゼロ点合わせ（Futaba既定False / NR-500既定True）
ZERO_ROWS        = 1000     # ゼロ点合わせに使う先頭行数
USE_EVENT_WINDOW = True     # イベント区間だけを解析（False で記録全体＝従来動作）
DETREND          = True     # FFT前に解析区間の平均を引く（False が従来動作）
WINDOW           = "hann"   # "hann" / "none"（"none" が従来の矩形窓）
```

グラフの見た目（`LOG_Y` / `X_MIN,X_MAX,X_STEP` / `Y_MIN,Y_MAX`）は
**01・04 はセル2の先頭、02・05 はセル4の先頭、03・06 はセル4**にあります。

> **従来動作に戻したいとき**
> `USE_EVENT_WINDOW=False, DETREND=False, WINDOW="none", LOG_Y=False`
> にすると、改修前とほぼ同じ挙動になります。

### なぜ既定でイベント区間だけを解析するのか

実測すると、**信号があるのは記録のごく一部**でした。

| | イベント区間 | 記録全長 | 信号の割合 |
|---|---|---|---|
| Futaba CH03 | 2.572〜3.010 s | 20.0 s | **2.2 %** |
| NR-500 V03 | 2.105〜2.503 s | 5.0 s | **8.0 %** |

記録全体をFFTすると、残り97.8%のベースラインノイズが混入し、
振幅もデューティ比ぶん希釈されます（実ピーク 33.46 MPa → スペクトル上 1.75 MPa）。
0.05 Hz の周波数分解能を 0.44 秒のイベントに使うのも意味がありません。

### なぜ既定でY軸が対数なのか

カットオフ判断に必要な 5〜50 Hz 帯の振幅は 1e-3〜1e-1 MPa です。
リニアの 0〜5 MPa 軸では**すべてゼロに見えて**判断できません。

## 4. ゼロ点合わせ（NR-500）

NR-500 の `(1)HA-V03` / `(1)HA-V04` はどのファイルもゼロから始まらないため、
FFTの前にゼロ点合わせをします。方法は固定です。

> ### 最初の 1000 行の平均を、全行から引く

```python
def zero_adjust(df, n=1000):
    return df - df.iloc[:n].mean()
```

- **NR-500（04/05/06/07）は既定ON**、Futaba（01/02/03）は既定OFF
  （Futaba はベースラインが元から0近傍。実測 0.024〜0.079 MPa）
- 引いた値は画面表示され、CSV の `zero_offset_applied_MPa` 列にも残ります
  （実測: V03 = −0.1756 MPa、V04 = −1.1230 MPa）
- **波形の形は変わりません**。ピーク−ベースラインの差は保存されます
- 先頭1000行がイベントに重なっていないか自動で検査し、
  ずれていれば `zero_window_offset` フラグを立てます

### ★ ゼロ点合わせと `DETREND` は別物

| | 目的 | 引く値 |
|---|---|---|
| **ゼロ点合わせ** | センサのオフセットを物理的に補正 | **先頭1000行の平均** |
| **`DETREND`** | スペクトルの直流成分を消して見やすくする | 解析区間の平均 |

## 5. 品質フラグ（無言でスキップしない）

**波形の立ち上がるタイミングも形状もファイルごとに変わります。**
そのため各ファイルに品質フラグを付け、**セル末尾で必ず件数を表示**します。
`ok` 以外があればファイル名も出ます。全件はCSVで確認できます。

| フラグ | 意味 | 動作 |
|---|---|---|
| `ok` | 正常 | — |
| `no_event` | しきい値を超える区間がない | 記録全体にフォールバック |
| `event_at_edge` | イベントが記録端に接している（切れている可能性） | 端でクリップして続行 |
| `multiple_events(n)` | イベント候補が複数 | **面積が最大**のものを採用 |
| `low_snr(x)` | ピーク/ノイズ比が 20 未満 | 続行するが要確認 |
| `short_event` | 区間が64点未満でFFTに足りない | 記録全体にフォールバック |
| `zero_window_offset` | 先頭1000行がイベントに重なっている | 続行するが要確認 |
| `zero_window_noisy` | 先頭1000行の分散が異常に大きい | 同上 |

### ばらつきに強くするための工夫

- **基準線は中央値とMADで推定**。「記録の前半は静穏」と仮定しないので、
  イベントが記録の先頭にあっても末尾にあっても正しく求まります
- **イベントは面積が最大の区間を採用**。事前のノイズスパイクを本体と取り違えません
- **立上り時間はピークから遡って測定**。記録の先頭から探す素朴な実装だと、
  イベント前にノイズスパイクが1つあるだけで **2179 ms**（正しくは106 ms）になります

これらは実データを加工した8ケース（正常／先頭／末尾／イベントなし／2イベント／
振幅1/20の弱いショット／ノイズスパイク／ベースラインドリフト）で検証済みです。
回帰テストは `検証/test_fft_common.py` にあります。

```
.venv/Scripts/python.exe 検証/test_fft_common.py
```

## 7. 2つのファイル形式の違い

| 項目 | Futaba形式 | NR-500形式 |
|---|---|---|
| 例 | `038_210℃_080_1.0mm_futaba.csv` | `040_210℃_080_1.0mm.csv` |
| 計測器 | Futaba（圧力計） | KEYENCE NR-500 / NR-HA08 |
| 1行目 | `Time:2026/08/05 16:10:15` | `#BeginHeader,71` |
| 文字コード | ASCII | **Shift-JIS (cp932)** |
| ヘッダ行数 | 2行 + 列名1行 + 単位1行 | **71行** |
| 列名 | `CH01`〜`CH04` | `(1)HA-V01`〜`(1)HA-V04` |
| サンプリング周期 | 1 ms（1 kHz） | **5 µs（200 kHz）** |
| Nyquist周波数 | 500 Hz | **100,000 Hz** |
| データ点数 | 20,001 点（20秒） | **1,000,000 点（5秒）** |
| 単位 | **MPa**（そのまま） | **V**（要換算） |
| フッタ | なし | **3行あり**（`#BeginMark` 〜 `#EndMark`） |
| ファイルサイズ | 約 0.56 MB | 約 51 MB |

### チャンネルの対応

| Futaba | NR-500 |
|---|---|
| `CH03` | `(1)HA-V03`（コード上は `V03`） |
| `CH04` | `(1)HA-V04`（コード上は `V04`） |

### 単位換算（NR-500のみ）

> ### 圧力[MPa] = 電圧[V] × 20

NR-500 はヘッダの `スケーリング` が `OFF` で生の電圧値のまま記録されています。
係数は `fft_common.py` の `VOLT_TO_MPA` 1箇所に集約してあります。

## 8. 実測で分かっていること

サンプル2ファイル（`加工対象ファイルサンプル`）を実測した結果です。

### 信号を保つのに必要な帯域

| ch | ピーク | 立上り(10-90%) | 必要帯域 | f99 | f99.9 |
|---|---|---|---|---|---|
| Futaba CH03 | 33.46 MPa | 106.0 ms | 3.3 Hz | 9.9 Hz | 17.0 Hz |
| Futaba CH04 | 22.78 MPa | 77.0 ms | 4.5 Hz | 10.8 Hz | 18.1 Hz |
| NR-500 V03 | 27.76 MPa | 92.0 ms | 3.8 Hz | 10.1 Hz | 17.3 Hz |
| NR-500 V04 | 22.16 MPa | 80.0 ms | 4.4 Hz | 10.3 Hz | 19.2 Hz |

**4チャンネルすべてで f99.9 が 17〜20 Hz に収まり、両計測器で一致**しています。
ベースラインノイズは 0.046〜0.074 MPa RMS（ピークの0.2〜0.4%）。

### カットオフ掃引（サンプル2ファイル）

| カットオフ | ピーク誤差（中央 / 最悪） | ノイズ低減（中央） |
|---|---|---|
| 5 Hz | −20.2% / −23.6% | 2.1倍 |
| 10 Hz | −8.3% / −11.3% | 5.7倍 |
| **20 Hz** | −2.6% / −5.7% | **6.3倍** |
| **30 Hz** | −1.3% / −4.4% | 6.0倍 |
| 50 Hz | −0.9% / −3.8% | 3.3倍 |
| 100 Hz | −0.8% / −3.7% | 3.1倍 |

**ノイズ低減は20〜30 Hzで頭打ち**になり、それ以上上げても改善しません。
一方 20 Hz を下回るとピークが急速に潰れます。→ **20〜30 Hz が有力**。

※これはサンプル2ファイルのみの結果です。**必ず 07 を全ファイルに対して実行**して、
実際のデータで確認してください。

### ⚠️ Futaba の高周波側は信用できない

PSD（MPa²/Hz）を同じ帯域で比べると、Futaba は NR-500 の 10〜24倍あり、
**50 Hz から Nyquist(499 Hz) まで真っ平ら**です。

| 帯域 | Futaba | NR-500 | 比 |
|---|---|---|---|
| 50-100 Hz | 9.11e-06 | 9.13e-07 | 10.0倍 |
| 400-499 Hz | 5.49e-06 | 2.25e-07 | 24.4倍 |

エイリアシングかノイズフロアです。
**カットオフの判断に Futaba の高周波側を使わないでください。**
高周波側は NR-500 の線を見てください（07のセル6は形式別に描くので一目で分かります）。

## 9. 既知の問題・注意点

### 出力フォルダの場所

`os.getcwd()` の直下に作られます。VS Code のワークスペースルートが
`フーリエ変換` なら、`コードフォルダ` の中ではなく `フーリエ変換` 直下です。

### 結果まとめフォルダ の既存PNGについて

`結果まとめフォルダ` に入っている画像は**改修前のコードの出力**です。
記録全体をFFTしリニア軸で描いたものなので、上記の理由により
カットオフ判断には使えません。作り直す場合は 03 / 06 を実行してください。

なお改修前の 03 は出力名に末端フォルダ名しか使っておらず、
`0.5mm/190℃` と `1.0mm/190℃` が同名で上書きされていました
（末端フォルダ12件を処理したのに各材料9枚しか残っていない原因）。
現在は相対パス全体を使うので衝突しません。

### 元ファイルは読み取り専用

7本すべて、加工対象CSVには `pd.read_csv` と `open(..., "r")` しか行いません。
ゼロ点合わせ・DC除去・窓関数はすべてメモリ上の操作で、元ファイルには書き戻しません。
書き込み先は `fft_results*` / `fft_cutoff_analysis` の PNG・CSV のみです。
（回帰テストで SHA-256 が不変であることを確認しています）

### 次のステップ：実際にローパスをかけるとき

- **scipy が未インストールです。** `uv add scipy` で追加してください
- 07 のFFTローパスは**評価用**です。実適用には
  `scipy.signal.butter` + `filtfilt`（ゼロ位相）を使ってください。
  ゼロ位相でないとピーク圧力の発生時刻がずれます
- FFTのブリックウォールはリンギングを起こします
  （実測で fc=5 Hz のときベースラインノイズがむしろ増加しました）
