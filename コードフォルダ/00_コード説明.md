# コードフォルダ 説明書

圧力経時変化のフーリエ変換（FFT）用ノートブック **6本** の使い分けと実行手順。

計測器が2種類あり、**CSVの形式がまったく違う**ため、コードも2系統に分かれています。
**形式に合わないコードを実行しても正しい結果は出ません。** まず形式を見分けてください。

---

## 1. 早見表：どのファイルにどのコードを使うか

### まず手元のCSVの「1行目」を見る

```
CSVの1行目
├─ "Time:2026/08/05 16:10:15" のように Time: で始まる
│    → Futaba形式  → 01 / 02 / 03 を使う
│
└─ "#BeginHeader,71" のように #BeginHeader で始まる
     → NR-500形式（KEYENCE） → 04 / 05 / 06 を使う
```

ファイル名に `_futaba` が付いていれば Futaba形式ですが、
**付いていないファイルもあるため 1行目で判断するのが確実**です。

### 用途 × 形式の対応表

| やりたいこと | Futaba形式 | NR-500形式 |
|---|---|---|
| 1ファイルだけ画面で確認する | **01** | **04** |
| 全ファイルを1枚ずつPNGにする | **02** | **05** |
| フォルダ単位で重ね描きしてまとめる | **03** | **06** |

---

## 2. 実行タイミングの指針

**① まず 01 / 04 で1ファイルだけ見る**
新しい計測データを触るとき、最初に1ファイルだけ開いて
「ピークの位置と大きさが想定どおりか」を確認します。画面表示のみで保存はしません。
ここで異常があれば、以降の一括処理を回す前に気付けます。

**② 次に 03 / 06 で本番のまとめグラフを作る**
温度・板厚などの条件ごとに重ね描きしたグラフを作ります。**これが成果物**です。
`結果まとめフォルダ` に入っているのはこの出力です。

**③ 02 / 05 は原因調査用**
③のまとめグラフで1本だけ極端に外れた線があるとき、
個別PNGを見て「どのファイルが原因か」を特定するために使います。
最初から②の代わりに使うものではありません（枚数が多くなりすぎるため）。

## 4. 2つのファイル形式の違い

| 項目 | Futaba形式 | NR-500形式 |
|---|---|---|
| 例 | `038_210℃_080_1.0mm_futaba.csv` | `040_210℃_080_1.0mm.csv` |
| 計測器 | Futaba（圧力計） | KEYENCE NR-500 / NR-HA08 |
| 1行目 | `Time:2026/08/05 16:10:15` | `#BeginHeader,71` |
| 文字コード | ASCII | **Shift-JIS (cp932)** |
| ヘッダ行数 | 2行 + 列名1行 + 単位1行 | **71行** |
| 列名の位置 | 3行目 | 71行目（`#EndHeader,...`） |
| 列名 | `CH01`〜`CH04` | `(1)HA-V01`〜`(1)HA-V04` |
| 時間列 | `Elapsed Time`（経過秒・1列） | 日時文字列＋マイクロ秒の**2列** |
| サンプリング周期 | 1 ms（1 kHz） | **5 µs（200 kHz）** |
| Nyquist周波数 | 500 Hz | **100,000 Hz** |
| データ点数 | 20,001 点（20秒） | **1,000,000 点（5秒）** |
| 周波数分解能 | 0.05 Hz | 0.2 Hz |
| 単位 | **MPa**（圧力そのもの） | **V**（電圧・要換算） |
| フッタ | なし | **3行あり**（`#BeginMark` 〜 `#EndMark`） |
| ファイルサイズ | 約 0.56 MB | 約 51 MB |

### チャンネルの対応

| Futaba | NR-500 |
|---|---|
| `CH03` | `(1)HA-V03`（コード上は `V03`） |
| `CH04` | `(1)HA-V04`（コード上は `V04`） |

## 5. 単位換算（NR-500形式のみ）

> ### 圧力[MPa] = 電圧[V] × 20

NR-500 はヘッダの `スケーリング` が `OFF` になっており、
**生の電圧値のまま**記録されています。そのため圧力に直すには換算が必要です。
Futaba形式は最初から MPa なので換算は不要です。

換算係数は 04 / 05 / 06 の**セル1にある `VOLT_TO_MPA` の1箇所**に集約してあります。
係数を変えるときはここだけ書き換えてください。

```python
VOLT_TO_MPA = 20.0
```

## 6. 既知の問題と注意点

### ⚠️ 既存 03 はエラーを黙って握り潰す

03 のセル5は `except Exception: error_count += 1` で**理由を表示せず**、
セル6は `except Exception: pass` で**完全に無言**です。

このため、**NR-500形式のファイルが混ざったフォルダを 03 で処理すると、
そのファイルはグラフから静かに抜け落ちるだけで、まったく気付けません。**
「線の本数が少ない気がする」以外に手がかりが残りません。

04 / 05 / 06 では、対象外ファイルの件数と例を必ず表示するようにしてあります。

### ⚠️ 既存 03 は出力ファイル名が衝突する

03 の保存名は末端フォルダ名だけを使っています。

```python
output_image_name = f"{last_folder_name}_{col_name}_combined_fft.png"
```

このため `0.5mm/190℃` と `1.0mm/190℃` が**どちらも `190℃_CH03_combined_fft.png`
になり、後から処理された方で上書き**されます。
実際、末端フォルダ12件を処理したのに `結果まとめフォルダ` には各材料9枚しか
残っておらず、板厚の区別が失われています。

05 / 06 ではメインフォルダからの相対パスを使うことで解消済みです
（`0.5mm_190℃_V03_combined_fft.png` のようになります）。

### 形式を間違えたときに何が起きるか

| 実行したコード | 渡したファイル | 起きること |
|---|---|---|
| 01 | NR-500形式 | `UnicodeDecodeError` で停止（気付ける） |
| 02 | NR-500形式 | エラー名を印字してスキップ（気付ける） |
| 03 | NR-500形式 | **無言でスキップ（気付けない）** |
| 04 | Futaba形式 | 「NR-500形式ではありません」と案内して正常終了 |
| 05 / 06 | Futaba形式 | 対象外として件数・例を表示して除外 |

### 出力フォルダの場所

`os.getcwd()` の直下に作られます。VS Code でワークスペースのルートを
`フーリエ変換` フォルダにしている場合、`コードフォルダ` の中ではなく
`フーリエ変換` 直下に `fft_results_*` が作られます。

### NR-500 の高周波帯域について

NR-500 は Nyquist が 100 kHz あり、既定の表示帯域 0〜150 Hz は
**利用可能な帯域のごく一部**です（Futaba版と比較できるようこの値にしてあります）。
高周波側を見たい場合は、04/05 なら `F_HI`、06 なら `x_max` を大きくしてください。

ただし 06 は計算済みスペクトルを `x_min〜x_max` の範囲に絞って保持しているため、
**帯域を広げる場合はセル4を書き換えたうえでセル5から実行し直す必要があります**
（帯域を狭める分にはセル6・7の描画だけで足ります）。
